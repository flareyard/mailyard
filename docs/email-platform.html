What Cloudflare gives us, and what it doesn't

Cloudflare now covers the whole mail transport: receive, send, events, suppression and SMTP. What's missing is the product layer: mailboxes, contacts, campaigns and automations. That layer is what this app is.

GA · free + paid

Email Routing

Inbound mail to your domain, unlimited on both plans. A rule sends an address, or a catch-all, to a Worker's email() handler, which gets the raw MIME stream and can forward(), reply() or setReject(). Rules can now live in Wrangler config (addresses, 4 Sep 2026). Inbound mail failing the sender's DMARC policy, and mail from RBL-listed IPs, is rejected before our code runs.

beta · Workers Paid

Email Sending

Send to any recipient through a Workers binding, REST, or authenticated SMTP. 3,000 a month included, then $0.35 per 1,000. Automatic DKIM and ARC signing, a cf-bounce return path, an account suppression list, and a reputation API. Sends to your own verified addresses are free.

since 15 Jul 2026

Sending events on Queues

Six events per sending domain: delivered, deferred, bounced (hard/soft), failed, rejected, complained, each with SMTP status and response. This is Plunk's webhook layer, built in.

beta since 8 Jun 2026

SMTP submission

smtp.mx.cloudflare.net:465, implicit TLS, username api_token, password a Cloudflare API token with Email Sending: Edit. Any SMTP library or mail client can send through it. The catch: that token can send from every onboarded domain on the account.

API

Zones, scan, import, activation

POST /zones (Zone Edit), /dns_records/scan/trigger plus /scan/review for the quick scan, /dns_records/import for a BIND file, PUT /activation_check to re-check nameservers. Everything the dashboard's onboarding does is scriptable.

not via API yet

Registrar transfers

The Registrar API (beta) can search, check and register, but transfers, renewals and contact updates are not available through it. Moving a registration to Cloudflare stays a dashboard step. Moving DNS to Cloudflare doesn't need a transfer, only a nameserver change at the current registrar.

Not offered by Cloudflare, measured in the API spec today: mailboxes, IMAP or POP access, contacts, lists, campaigns, automations, templates, open and click tracking. Workers also can't accept inbound TCP, so a Worker can't be an IMAP server. It can still be an IMAP client through connect(), which is how mailbox import works.

A platform feature every app uses

One-click domain import from any registrar

Domain import belongs in the platform, not in the email app, because every Flareyard app needs a domain. It runs as a Workflow, so a move that takes hours to propagate survives restarts, retries each step, and emails you when the domain is live. It's "one click" when the registrar has an API, and a guided two-minute task when it doesn't.

  1. Detect

    Look the domain up over RDAP (public HTTPS) for the registrar, current nameservers and DNSSEC state. Pick the matching connector, or the guided path.

    Worker fetch · no credentials

  2. Collect every record

    Three sources, merged. (1) Cloudflare's quick scan after POST /zones. (2) The old provider's own DNS export when its API is connected: Hostinger and Spaceship both have one. (3) Our own DNS-over-HTTPS probe of the names quick scan tends to miss, such as _dmarc, DKIM selectors (google._domainkey, selector1/2, spacemail._domainkey, hostingermail-*, k1, s1/s2), autodiscover, _sip/_srv, verification TXTs and every CNAME the website uses.

    /zones/{id}/dns_records/scan/trigger · /scan/review · /dns_records/batch

  3. Review the diff

    One screen: what moves, what's new, what conflicts. Mail records are forced DNS only. Anything we can't classify is flagged, never silently dropped. Nothing changes at the registrar until you confirm.

  4. Make it safe to switch

    If DNSSEC is on, turn it off at the registrar first (through the API where it exists, otherwise a guided step), because switching nameservers with DNSSEC on takes the domain offline. Then wait out the old DS TTL.

  5. Switch nameservers

    Connector path: one API call sets Cloudflare's two assigned nameservers. Guided path: a deep link to the registrar's nameserver page, both names with copy buttons, and a live checker that turns green the moment the registry shows them.

  6. Wait for active

    The Workflow sleeps and polls RDAP and DoH with backoff, calls activation_check, and verifies that MX and the website still resolve the same as before the move. You get an email when it's active, or when something resolved differently.

    step.sleep · Schedule.exponential · PUT /zones/{id}/activation_check

  7. Finish

    Re-enable DNSSEC on Cloudflare and push the DS record to the registrar (API or guided). Delete the registrar API key we used. Optionally offer the dashboard link to transfer the registration to Cloudflare Registrar.

Real mailboxes with no mail server

How an inbox works on Cloudflare

Cloudflare doesn't host mailboxes, so the app is the mailbox. A catch-all routes every address on the domain to one Worker. That Worker stores the message and files it into a Durable Object per mailbox, which holds that mailbox's index in its own SQLite database, pushes new mail live to open tabs over hibernating WebSockets, and uses alarms for snooze and scheduled send. Adding an address is a database row, not a Cloudflare rule.

  1. Receive

    Email Routing accepts SMTP on Cloudflare's MX, checks SPF, DKIM, DMARC and ARC, and hands the message to email(). Messages over 25 MiB are rejected at the door.

  2. Store first

    The raw .eml goes to R2 under a content hash before anything else happens. If parsing or indexing fails, nothing is lost and a Queue retries it.

  3. Parse and resolve

    postal-mime (already pinned in MBPrep at 2.7.6) splits headers, bodies and attachments. Attachments go to R2. The recipient resolves to a mailbox, alias, group or catch-all; unknown addresses either bounce or land in catch-all, which you choose per domain.

  4. Filter

    Your rules run (from, to, subject, list-id → label, archive, forward, auto-reply, webhook), then a spam score: authentication results plus a classifier behind an Effect service (Workers AI on Cloudflare, any OpenAI-compatible endpoint off it).

  5. File into the mailbox

    The MailboxDO threads the message by Message-ID, In-Reply-To and References, writes the index row and its full-text entry, and pushes it to every connected client.

  6. Fan out

    An event goes on the mail-events Queue so other apps can react: Hermes's email lane, the support inbox app, your webhooks.

  7. Reply

    Compose in the web app. Sending goes through Email Service with the right In-Reply-To and References headers, and the sent copy is filed into the same thread. Attachments over the 5 MiB outbound limit become expiring R2 links automatically.

Four ways to read your mail

phase M3

The web app, installable

Gmail mode, free

Route an address to your Gmail (a free verified destination) and add it in Gmail's "Send mail as" through smtp.mx.cloudflare.net:465. That gives you a real Gmail inbox for your domain with no seat cost. It suits one owner, because the token can send as any domain on the account.

spike S8

JMAP over HTTPS

JMAP is mail access over HTTP and JSON, so a Worker can serve it natively. Client support is narrower than IMAP, so it's a bonus, not the plan.

not native

IMAP for Outlook and Apple Mail

Workers can't accept inbound TCP. IMAP would need a Container behind a TCP front, which isn't free and isn't scale-to-zero. Parked until there's a real need, and priced first if there is.

Moving in

Import an existing mailbox

A Workflow logs in to the old provider over IMAP using Workers' connect() (TLS to port 993), copies each folder in batches of UIDs with a checkpoint per batch, and resumes where it stopped. This covers Hostinger, Spacemail and Gmail with an app password. It runs before MX moves, then catches up the gap afterwards.

Coexisting

Keep Google Workspace on the apex

MX is per hostname, so mbprep.app can keep Workspace while support.mbprep.app or in.mbprep.app routes to this app. Whether Email Routing accepts a subdomain is spike S3.

Moving out

Export everything

mbox and per-message .eml to a zip in R2, with a signed download. Owning it means you can leave.

System design

Three Workers, three Durable Objects, one database, no server

Everything runs in the user's own Cloudflare account. Cloudflare owns when things run and that they persist: Durable Objects, alarms, Workflows, Queues. Effect owns how each handler behaves: typed failures, retry schedules, and swappable services.

// Inbound: store first, then everything else is retryable work.
export default {
  async email(msg, env, ctx) {
    await Effect.runPromise(
      Inbound.receive(msg).pipe(            // R2 put by content hash, then parse
        Effect.flatMap(Inbound.file),        // resolve → rules → spam → MailboxDO
        Effect.catchTag("Unroutable", (e) => Effect.sync(() => msg.setReject(e.reason))),
        Effect.catchAll((e) => Queue.retryLater(env.MAIL_EVENTS, e)), // raw is safe in R2
        Effect.provide(Live(env)),
      ),
    )
  },
}

// Sending: the governor decides when; the Sender decides how.
const sendOne = (m: Outgoing) =>
  Governor.acquire(m.recipientDomain).pipe(  // waits for quota + pacing
    Effect.zipRight(Sender.send(m)),
    Effect.retry({ schedule: transient, while: (e) => e._tag === "Deferred" }),
    Effect.tap((id) => Ledger.recordSent(m, id)), // events Q fills in the rest
  )
Verification

Every phase ends in a check you can run

Golden .eml fixtures (multipart, inline images, non-UTF-8 charsets, 24 MiB, broken MIME) go through inbound under Miniflare. Threading is property-tested. Auth results for real sends are read back from a Gmail inbox. A seed list of your own verified addresses tests campaigns for free, since those sends don't count toward quota.

Cost discipline

The bill follows the work

Nothing polls. Waits are Workflow sleeps and DO alarms, and live pushes are hibernating WebSockets. Tracking writes go to Analytics Engine, not D1 rows. A usage page shows the real meter against the included 3,000 a month and the daily quota.

Security

Keys and content

API keys are stored hashed. Registrar keys exist only for the lifetime of one Workflow. Raw mail never leaves the user's R2. HTML mail renders in a sandboxed iframe with remote images proxied and blocked until you allow them. Every send and setting change goes to the audit log.
