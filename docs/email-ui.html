Rules for every screen

What every screen does the same way

Real numbers only

Every figure comes from an endpoint. Where there isn't enough data yet (fewer than 100 sends, the minimum Cloudflare's reputation policy uses), the screen says "not enough data yet" instead of showing a rate.

Live where it matters

New mail, campaign progress, import progress and domain activation update without a refresh, through a WebSocket per mailbox and per workspace. Everything else refreshes on focus.

Every list is a URL

Filters, sort, search and the open item live in the query string, so any view can be bookmarked, shared with a teammate, or opened by an agent.

Keyboard first, ⌘K everywhere

A command palette reaches every screen, mailbox, contact, campaign and action. The mail screens carry the usual single-key shortcuts.

Brand

Flareyard tokens (Geist structure, ember accent). Colour carries meaning only: green delivered or passing, amber deferred or warning, red bounced, failing or at risk. Charts use the tokens' data palette, never Cloudflare orange.

Phone

Overview, mail (list, thread, compose) and contact lookup get full phone layouts and Web Push. The builders (segments, campaigns, automations) are desktop-first and read-only on a phone.

An empty workspace

First run

A brand-new workspace doesn't show an empty dashboard. It shows a checklist that becomes the Overview once it's finished.

  1. Add a domain

    Pick a domain already on Cloudflare, or import one (the domain import flow). Shows each domain's current state: active, pending nameservers, or not on Cloudflare.

    GET /v1/domains/candidates · POST /v1/domains

  2. Turn on mail

    Shows the records that routing and sending will add (MX, SPF, DKIM, the cf-bounce return path, DMARC), then a live check of each, ticking green as it passes.

    POST /v1/domains/:id/enable · GET /v1/domains/:id/checks

  3. Create your first mailbox

    Address, display name, who can read it, signature. Suggests hello@.

    POST /v1/mailboxes

  4. Send yourself a test

    Sends to your verified address (free), then shows the result: delivered, with SPF, DKIM and DMARC as they were seen.

    POST /v1/test-send · ws: workspace

  5. Bring your old mail (optional)

    IMAP host, username and password (app password for Gmail). Shows a folder list with message counts before anything copies.

    POST /v1/imports/mailbox · GET /v1/imports/:id

  6. Bring your contacts (optional)

    CSV upload, or skip.

    POST /v1/imports/contacts

Definition of done, backend

Every row works without a UI

Each endpoint has a contract test against its Schema, a fixture response checked into test/fixtures/api/, and a curl example in the generated docs. The MCP server exposes the same operations, so an agent can drive the whole product before any screen exists.

Definition of done, UI

Every screen against fixtures, then live

Each screen renders its empty, loading, error and full states from fixtures first, then against your real account. Each passes the responsive audit at phone, tablet and desktop widths.

What this changes in the plan

Read models the backend owes

Several screens need precomputed views, not raw tables: per-day stats rollups (from the events Queue), the "needs you" attention query, segment counts, per-node automation counts and campaign ETAs. These are built in the backend phases, not bolted on when the UI arrives.
